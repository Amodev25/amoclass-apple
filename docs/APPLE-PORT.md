# بناء بيئة آبل (iOS + macOS) — دليل ما حدث بالتفصيل

> آخر تحديث: 2026-09-12
> الحالة: **iOS مثبت عمليًا** (تسجيل دخول + فيديو مشفّر شغال على Appetize).
> **macOS يُقلع بنجاح على رنر آبل حقيقي، لكن لم يُسجَّل دخول ولم تُختبر الحماية عليه.**

هذا ملف سجل، لا ملف تسويق. الغرض منه أن أي شخص (أو أي جلسة جديدة) يقدر يعيد بناء البيئة من الصفر، ويعرف الفخاخ قبل ما يقع فيها، ويميّز بين "الشيء اتأكد" و"الشيء يبدو صح".

---

## ١. لماذا مجلد ثالث ولم نوحّد المجلدات؟

المشروع فيه تطبيقان للطالب:

| المجلد | المنصة |
|---|---|
| `amoclass_player` | Windows |
| `amoclass_player_android` | Android |
| `amoclass_player_apple` | **iOS + macOS** (الجديد) |

الاقتراح الأول كان توحيد الاثنين القديمين في تطبيق واحد متعدد المنصات. قياس الفرق بينهما أظهر **٥٤٥١ سطرًا متباعدًا** — الاثنان ليسا نسختين من شيء واحد، بل **تفرّعان** ابتعدا عن بعضهما على مدى شهور. التوحيد يعني لمس كل مسار حرج في تطبيقين يعملان حاليًا بلا شبكة اختبارات تحميهما.

القرار (اقتراح صاحب المشروع، وهو الصحيح): **لا نلمس ويندوز ولا أندرويد إطلاقًا**، ونصنع مجلدًا ثالثًا لآبل مفروزًا من نسخة أندرويد.

الثمن المقبول: تكرار الكود. المكسب: عطل في آبل لا يمكنه أن يكسر منصة تعمل الآن.

## ٢. ما الذي بُني فعليًا

### أ. حزمة المنصة الأصلية — `amo_platform_apple/`

إضافة (plugin) فيدرالية واحدة تخدم النظامين معًا عبر شجرة مصدر واحدة:

```yaml
flutter:
  plugin:
    platforms:
      ios:   { pluginClass: AmoPlatformPlugin, sharedDarwinSource: true }
      macos: { pluginClass: AmoPlatformPlugin, sharedDarwinSource: true }
```

`sharedDarwinSource: true` هو المفتاح: مجلد `darwin/` واحد يخدم iOS و macOS بدل مجلدين متطابقين يفترقان مع الوقت.

محتويات `darwin/Classes/`:

| الملف | الأصل | الدور |
|---|---|---|
| `amo_stream.c` | **منقول حرفيًا من أندرويد** | فك التشفير AES-256-CTR وقراءة الحاوية v2 |
| `aes256.c/.h`, `sha256.c/.h` | منقولة حرفيًا | التعمية |
| `amo_stream_apple.c/.h` | **جديد** | بديل طبقة JNI — يسجّل بروتوكول `amo://` في mpv |
| `AmoPlatformPlugin.m` | **جديد، ~٤٠٩ سطر Objective-C** | القنوات الأربع + هوية الجهاز |

**التعديل على `amo_stream.c`: ١٥ سطرًا مضافًا، صفر محذوف.** كل ما احتاجه الملف هو فرع `#elif defined(__APPLE__)` يستبدل `<android/log.h>` بكتابة على `stderr`. آبل نظام POSIX، فـ `mmap` و `madvise` و `mlock` كلها موجودة أصلًا.

هذا أهم رقم في الملف كله: **منطق فك التشفير لم يُعد كتابته، ولذلك لم يحتج إعادة تدقيق أمني.**

**لماذا Objective-C وليس Swift؟** لأنني لا أملك ماك لأترجم عليه محليًا. Objective-C يستدعي دوال C مباشرة بلا جسور ولا module maps ولا bridging headers — ثلاثة مصادر أخطاء لا يظهر أيٌّ منها إلا وقت الترجمة. حين تكون كل دورة تصحيح رحلة ذهاب وعودة إلى خادم في GitHub مدتها دقيقتان، تختار اللغة التي تقلل عدد الدورات، لا الأجمل.

### ب. تطبيق فلاتر — `amoclass_player_apple/`

مفروز من `amoclass_player_android`. مجموع ما تغيّر في كود Dart: **~٢٩٥ سطرًا** موزعة هكذا:

| الملف | أسطر متغيرة | السبب |
|---|---|---|
| `screens/player_screen.dart` | 130 | زووم + اختصارات كيبورد للماك، وتقييد قفل الاتجاه بالموبايل |
| `core/focus_mode_platform.dart` | 71 | وضع التركيز على الماك، معطّل تمامًا على iOS |
| `core/anti_capture.dart` | 34 | `NSWindowSharingNone` للماك، درع كشف للآيفون |
| `main.dart` | 34 | قفل الاتجاه لا يُستدعى على سطح المكتب |
| `services/session_service.dart` | 8 | الإبلاغ عن المنصة الحقيقية |
| `services/auth_service.dart` | 5 | الإبلاغ عن المنصة الحقيقية |
| الباقي | 10 | لمسات صغيرة |

وملفان جديدان يستحقان الشرح:

**`lib/core/platform_ui.dart`** — يسمّي القدرات لا الأنظمة:

```dart
static bool get supportsOrientationLock    => isMobile;
static bool get supportsPointerAndKeyboard => isDesktop;
```

الفرق ليس تجميليًا. `if (Platform.isMacOS)` في شاشة المشغّل تعني أن إضافة iPad أو Vision Pro لاحقًا تتطلب مطاردة كل `isMacOS` في المشروع. أما `if (supportsPointerAndKeyboard)` فتبقى صحيحة بلا تعديل.

**`lib/core/platform_identity.dart`** — ما يُقال للخادم:

```dart
static String get current => Platform.isMacOS ? macos : ios;
```

## ٣. كيف نبني لآبل بلا ماك؟

هذه هي الحلقة التي جعلت المشروع ممكنًا أصلًا:

```
ويندوز (تحرير) ← git push ← GitHub Actions (ماك حقيقي) ← قراءة اللوج ← إصلاح ← تكرار
```

ملف `.github/workflows/apple-build.yml` فيه أربع وظائف:

| الوظيفة | المنصة | الغرض |
|---|---|---|
| `analyze` | **ubuntu** | `flutter analyze` + `flutter test` |
| `macos` | macos-latest | `flutter build macos --debug` |
| `ios` | macos-latest | `flutter build ios --debug --simulator` |
| `ipa` | macos-latest | أرشيف جهاز + تغليفه `.ipa` يدويًا |

**لماذا `analyze` على لينكس؟** لأن رنر الماك في GitHub **يُحاسَب بعشرة أضعاف** سعر رنر لينكس. خطأ إملائي في Dart لا يستحق أن يُكتشف على ماك. البوابة الرخيصة تسبق الغالية.

**لا حساب آبل ولا أسرار (secrets) في هذه الحلقة كلها.** البناء غير موقّع، وهذا كافٍ تمامًا لإثبات أن الكود يُترجم ويُربَط.

### الدفاع ضد "الأخضر الكاذب"

بناء ناجح **لا يثبت** أن كود C وصل إلى البرنامج. لو توقف نمط المصادر في الـ podspec عن مطابقة ملفات `.c` يومًا ما، التطبيق يُبنى ويُثبَّت بنجاح ولا يظهر العطل إلا حين يضغط الطالب "تشغيل".

لذلك `scripts/verify_native_symbols.sh` يفحص **كل** ملف Mach-O داخل الحزمة ويطالب بوجود ثلاثة رموز مُعرَّفة:

```
_amo_register_protocol   _amo_open   _amo_set_credentials
```

ويميّز بين حالتين مختلفتين تمامًا:

- **"لم أجد أي ملف Mach-O"** ← *الفحص* معطوب
- **"الرموز غائبة"** ← *البناء* معطوب

كذلك `if-no-files-found: error` على رفع المخرجات، حتى لا ينجح البناء وهو لا ينتج شيئًا.

## ٤. المشاكل التي واجهتها وكيف حُلّت

### 🔴 ١. الانهيار عند الإقلاع: مكتبة غير موقّعة (أخطر مشكلة)

**العرض** — البناء أخضر تمامًا، والتطبيق يموت لحظة فتحه على السيمولاتور:

```
dyld: Library not loaded: @rpath/Ass.framework/Ass
  not valid for use in process: Trying to load an unsigned library
```

**السبب الجذري** — الوظيفة كانت تمرّر `--no-codesign` لبناء السيمولاتور. هذا العلم يضبط `CODE_SIGNING_ALLOWED=NO`. بناء السيمولاتور فعلًا **لا يحتاج** شهادة ولا حساب آبل — لكن `dyld` يرفض تحميل إطار مضمّن **بلا أي توقيع إطلاقًا**، والعلم يكبت حتى التوقيع المحلي (ad-hoc) الذي كان Xcode سيضعه تلقائيًا.

**الحل** — حذف `--no-codesign` من وظيفة السيمولاتور، وإبقاؤه على أرشيف الجهاز حيث هو صحيح (مزارع الأجهزة السحابية تعيد توقيع الـ IPA بشهادتها).

**الدرس، وهو أهم درس في الملف:** الـ CI **لم يكن ليمسك هذا أبدًا**. البناء الأخضر يثبت أن الكود تُرجم ورُبط، لا أنه يُقلع. الفرق بين الاثنين هو بالضبط الفرق بين "خلصنا" و"لسه مخلصناش". *(مسجّل في `.wolf/buglog.json` تحت `bug-005`)*

### 🔴 ٢. التطبيق كان ينتحل شخصية أندرويد

**كيف ظهرت** — سؤال من صاحب المشروع: "موقع الويب مفيهوش لا ماك ولا آيفون، هل ده هيضر في حاجة؟"

**ما كُشف** — التطبيق الجديد كان يرسل `'platform': 'android'` حرفيًا إلى الخادم في أربعة مواضع. النتيجة ليست تجميلية: نظام ربط المقاعد يقيّد الطالب بمنصة محددة، وانتحال المنصة **يُعطّل هذا البُعد من الترخيص بالكامل** (ربط الجهاز نفسه ظل سليمًا، لحسن الحظ).

**الحل — عبر الطبقات الثلاث:**

- التطبيق: `PlatformIdentity.current` بدل النص الثابت
- الخادم: `SeatPlatform` توسّع إلى `windows | android | ios | macos`، وخريطة تسميات ترجع "iPhone" و"Mac" بدل الأكواد الخام
- اللوحة: مُنتقي منصة بشبكة ٢×٢، وترجمات عربية/إنجليزية

**لا حاجة لترحيل قاعدة بيانات** — عمود `platform` نصّي بلا قيد `CHECK`، وقيد `enum` في Drizzle قيد على مستوى TypeScript فقط.

**الدرس:** سؤال عابر من المستخدم كشف عيبًا أمنيًا لم تكشفه لا الاختبارات ولا الـ CI. الأسئلة "الساذجة" عن تناسق النظام تستحق أن تُتَتبَّع حتى النهاية.

### 🟠 ٣. فحص الرموز أبلغ عن فشل وهمي

**العرض** — الفحص يقول إن الرموز الثلاثة كلها `MISSING` رغم أن البناء سليم.

**السبب** — كنت أستعمل `nm -a`، وهي تُخرج أيضًا **debug stabs** التي تذكر مسار كل ملف مصدر. وبما أن كل مسار في المشروع يحتوي كلمة `amoclass`، فإن البحث عن `amo` كان يغرق الرموز الحقيقية في آلاف الأسطر.

**الحل** — `nm -gU` (الرموز العامة المُصدَّرة التي *يعرّفها* هذا الملف).

**الدرس:** حين يفشل فحص، اسأل أولًا "هل الفحص معطوب أم الشيء المفحوص؟" ولهذا صار السكربت يفرّق بين الحالتين صراحةً في رسائله.

### 🟠 ٤. دفعة لم تُشغّل الـ CI إطلاقًا

**العرض** — أصلحت سكربت الفحص، ودفعت، ولم يحدث شيء.

**السبب** — `scripts/**` لم يكن ضمن مرشّح `paths:` في الـ workflow. أي أن **أي إصلاح لأداة الفحص لا يمكن أن يُشغَّل أبدًا.**

**الحل** — إضافة `scripts/**` إلى المرشّح، مع تعليق يشرح السبب.

**الدرس:** لو كان سكربت ما جزءًا من البناء، فتغييره يجب أن يُعيد البناء.

### 🟠 ٥. انهيار كامن على macOS 11

**العرض** — تحذير من المترجم: `kIOMainPortDefault is only available on macOS 12.0 or newer`.

**السبب** — حارسي كان يفحص `__MAC_OS_X_VERSION_MAX_ALLOWED` (نسخة الـ SDK التي أُترجم بها) بدل `__MAC_OS_X_VERSION_MIN_REQUIRED` (أدنى نسخة يدعمها التطبيق). النتيجة: يُترجم بنجاح على رنر حديث، وينهار على جهاز طالب يعمل بـ macOS 11.

**الحل** — استعمال `__MAC_OS_X_VERSION_MIN_REQUIRED`.

**الدرس:** تحذيرات التوفر في آبل ليست ضوضاء. هذه كانت ستصل إلى طالب حقيقي.

### 🟡 ٦. `flutter analyze` يفشل على ملاحظات info

**العرض** — الـ CI أحمر، وفحصي المحلي "نظيف".

**السبب** — كنت أمرر الناتج إلى `tail`، وهو ما **يخفي رمز الخروج** لأن الـ pipe يُرجع رمز آخر أمر. و`flutter analyze` يخرج بـ `1` حتى على ملاحظات من مستوى `info`.

**الحل** — إصلاح الملاحظات الستّ كلها، لا تمرير `--no-fatal-infos`.

**الدرس:** لا تمرر ناتج بوابة جودة عبر pipe إن كنت تهتم برمز خروجها. (محاولتي الأولى للإصلاح استهدفت السطر الخطأ أيضًا: المحلل يشير إلى *الجملة*، لا إلى `if` التي تسبقها.)

### 🟡 ٧. أخطاء أدخلتُها بنفسي في Objective-C

`retain_or_self` — دالة اخترعتها ولا وجود لها.
`kAudioDeviceTransportTypeairPlay` — حالة أحرف خاطئة، وفوق ذلك AirPlay ليس استماعًا خاصًا أصلًا.

الاثنان أُمسكا قبل الدفع. **الدرس:** حين تكتب بلغة لا تستطيع ترجمتها محليًا، راجع أسماء الـ API مقابل التوثيق بدل الاعتماد على الذاكرة.

### 🟡 ٨. تلف النصوص عبر heredoc في بايثون

`\n` تحوّلت إلى سطر جديد فعلي، وتسلسلات البايت أنتجت رموزًا مشوّهة داخل `amo_stream.c`. أعدت الملف الأصلي وطبّقت الرقعة عبر ملف في مجلد المسوّدات بلا أي هروب (escapes). كذلك: `/tmp` غير مرئي لبايثون على ويندوز.

### 🟡 ٩. إنذار كاذب: إلغاء بسبب التزامن

تشغيلة ظهرت فاشلة برسالة `Canceling since a higher priority waiting request exists`. هذه لم تكن عطلًا — كانت دفعتي السريعة التالية تُلغي السابقة عبر `concurrency.cancel-in-progress`.

**الدرس:** اقرأ سبب الفشل قبل تشخيصه.

### 🟡 ١٠. تراجعات عن قرارات اتخذتها

- **`CFBundleDocumentTypes`** — أضفتها ثم حذفتها. الادعاء بأن التطبيق يفتح ملفات `.amo` بلا معالج فعلي يجعل "افتح بـ Lockclass" تظهر للطالب ثم تتجاهل الملف بصمت. وعد كاذب أسوأ من غياب الميزة.
- **ذاكرة Gradle** — خفضتُها لحل انهيار، ثم أعدتها بناءً على طلب صاحب المشروع. *(تفصيل في القسم ٥)*

### ⚪ ١١. أخطاء في العملية لا في الكود

- **ادّعيتُ أن المشروع بلا مستودع git.** كنت قد فحصت الجذر فقط، بينما توجد **أربعة مستودعات متداخلة**. صححت الادعاء وأزلت `git init` الذي أنشأته في الجذر خطأً.
- **حد الحجم:** ملف ٧٣ ميجا تجاوز حد الإرسال (٣٠ ميجا)، فأعطيت المسار بدلًا منه.

## ٥. مشاكل جانبية ظهرت أثناء بناء APK أندرويد

هذه لا تخص آبل لكنها ظهرت في نفس الجلسة وتستحق التسجيل:

**Gradle 8.9 أقدم من الحد الأدنى لـ AGP 8.11.1** (وهو 8.13) ← رُفع `distributionUrl` إلى `gradle-8.13-bin.zip`.

**`Could not start thread DartWorker: 22`** ورمز خروج `-1073740791` ← الجهاز كان فيه **٩٦٤ ميجا حرة من أصل ٨ جيجا**. أوقفت عفاريت Gradle وخفّضت الكومة إلى `1536m`، فنجح البناء في ٥ دقائق بدل ١٣. صاحب المشروع طلب إرجاع `-Xmx3G` فأُعيدت، **مع تحذير صريح بأن الفشل قد يتكرر** وأن إغلاق كروم يساعد.

## ٦. قرارات متعمدة قد تبدو أعطالًا

اقرأ هذا القسم قبل أن "تصلح" أيًّا مما فيه.

| القرار | السبب |
|---|---|
| `AntiCapture.isSupported()` ترجع **false على iOS** | iOS **لا يملك** مقابلًا لـ FLAG_SECURE. المتاح هو الكشف عبر `UIScreen.isCaptured` ثم تغطية النافذة. هذا تخفيف لا منع، والواجهة يجب ألا تَعِد الطالب بما لا تستطيع. |
| وضع التركيز **معطّل كليًا على iOS** | لا يوجد مقابل لـ lock task. كل استدعاء محروس بـ `if (!isSupported) return;`. |
| `app-sandbox = false` على macOS | صندوق الرمل يمنع `DisableProcessSwitching`، وبدونه لا وجود لوضع التركيز. **الثمن: التطبيق لا يمكن نشره في Mac App Store.** خطة التوزيع هي DMG. |
| **لا روابط شراء أو تسجيل داخل التطبيق** | يحافظ على تصنيف "Reader App" لدى آبل ← بلا مشتريات داخلية وبلا عمولة ٣٠٪. إضافة رابط شراء واحد تُسقط هذا التصنيف. |
| `ios` و `macos` قيمتان منفصلتان لا `apple` واحدة | مقعد مقيَّد بـ "آبل" يسمح للطالب بالمشاهدة على الآيفون **وعلى** الماك بترخيص واحد. |
| لا `CFBundleDocumentTypes` ولا `UTExportedTypeDeclarations` في `Info.plist` | الحاوية تُعرَّف ببصمة البايتات (`AMOENC01`) لا باسمها، والمدرّس يختار الامتداد بحرية. و iOS يوجّه الملفات للتطبيقات بالامتداد/UTI، فأي إعلان هنا سيغطي امتدادًا واحدًا فقط ويجعل "افتح بـ Lockclass" تظهر ثم تفشل مع باقي الملفات. الاستيراد يمر بمنتقي الملفات داخل التطبيق (`FileType.any`) وهو بلا هذا القيد. |
| التكرار بين المجلدات الثلاثة | مشروح في القسم ١. |

## ٧. ما ثبت فعلًا وما لم يُختبر

### ✅ مثبت بتشغيل حقيقي (iOS، عبر Appetize)

تشغيلة واحدة ناجحة أغلقت سلسلة كاملة من المجاهيل دفعة واحدة:

- `dlsym(RTLD_DEFAULT, "mpv_stream_cb_add_ro")` **يجد الدالة** داخل نسخة mpv التي تشحنها `media_kit_libs_ios_video`. المسارات الاحتياطية في `amo_stream_apple.c` (`Mpv.framework/Mpv`, `libmpv.dylib` …) لم تكن مطلوبة على iOS أصلًا.
- بروتوكول `amo://` يُسجَّل بنجاح ← mpv يقرأ من دالة C خاصة بنا لا من ملف.
- `amo_stream.c` يمشي على كتل الـ ١٠ ميجا، ومعادلة الـ seek، والتشفير النمطي (١٦ بايت مشفّرة كل ١٦٠) — كلها صحيحة على معمارية آبل.
- تسجيل الدخول وربط المقعد بـ `platform: "ios"`.
- تحميل الـ plugin وقنواته، وهوية الجهاز من الـ Keychain.

### ✅ مثبت آليًا في الـ CI (macOS)

وظيفة `macos` صارت **تشغّل** التطبيق على رنر آبل حقيقي لا تبنيه فقط. ناتج أول تشغيلة:

```
launching: build/macos/Build/Products/Debug/AMO Player.app/Contents/MacOS/AMO Player
✅ still alive after 25s (pid 9998) — the app launches
AMO Player[9998] Running with merged UI and platform thread. Experimental.
flutter: The Dart VM service is listening on http://127.0.0.1:49220/...
flutter: media_kit: NativeReferenceHolder: Allocated 36652265472
```

ثلاث نتائج من هذه الأسطر:

1. **لا انهيار عند الإقلاع** ولا تقرير انهيار جديد — أي أن صنف العطل الذي أصاب iOS (مشكلة ١) غير موجود على الماك.
2. **آلة Dart تعمل** → التوقيع المحلي (ad-hoc) والصلاحيات (`allow-jit`) سليمة. كان هذا أكبر شك في اختبار نسخة debug غير موقّعة.
3. **`media_kit` أقلعت أصلًا على الماك** (`NativeReferenceHolder: Allocated`) → طبقة الفيديو الأصلية تُحمَّل.

### ❌ لم يُختبر بعد على macOS

الاختبار أعلاه يجيب على سؤال واحد فقط: **هل يُقلع التطبيق؟** لا يسجّل دخولًا (لا بيانات اعتماد على الرنر)، فلا يصل إلى:

- تشغيل درس مشفّر
- `NSWindowSharingNone` (منع التصوير)
- وضع التركيز
- اختصارات الكيبورد والزووم

وقيد إضافي: رنر GitHub معماريته **arm64**، فنسخة debug تُبنى للمعمارية المضيفة وحدها. أي أن ما ثبت هو **Apple Silicon**، أما أجهزة Intel فلم تُختبر.

هذه الأجزاء تحتاج **ماك حقيقي بيد إنسان**. ولا حل سحابي لها.

### 🚫 لا يمكن اختباره سحابيًا إطلاقًا

كل ما يخص منع التصوير. Appetize تبث **سيمولاتور** كفيديو، فـ `UIScreen.isCaptured` ترجع `false` دائمًا هناك، ولقطة شاشة من المتصفح لا تلمس كود iOS من الأساس. درع التسجيل يحتاج آيفون حقيقيًا، و `NSWindowSharingNone` يحتاج ماك حقيقيًا.

## ٨. الخطوة التي لا مفر منها: حساب آبل

**٩٩ دولارًا سنويًا صارت إجبارية، لا اختيارية.**

- **iOS**: لا يوجد مقابل لملف APK. المتجر هو الطريق الوحيد للتوزيع.
- **macOS**: حتى التوزيع خارج المتجر كملف DMG يتطلب **Developer ID وتوثيقًا (notarization)** من آبل — وكلاهما يمر بنفس الحساب.

كل ما سبق في هذا الملف أُنجز **بلا هذا الحساب**. لكن لا شيء يصل إلى طالب حقيقي بدونه.

`gh` غير موجود في `PATH` على هذا الجهاز، فالمسار الكامل مطلوب:

```bash
"/c/Program Files/GitHub CLI/gh.exe" run list --limit 1
```

```bash
"/c/Program Files/GitHub CLI/gh.exe" run watch <RUN_ID> --exit-status
```

```bash
"/c/Program Files/GitHub CLI/gh.exe" run view <RUN_ID> --log-failed
```

**تحقق دائمًا من ثلاث نقاط قبل تصديق نتيجة خضراء:**

1. هل تغييرك داخل مرشّح `paths:`؟ وإلا لم تُشغَّل التشغيلة أصلًا.
